# 存档桥 · GalSaveSync

通过已有的 WebDAV，在多台 Windows 电脑之间同步 Galgame 存档。

手动添加游戏和存档位置后，从客户端启动游戏即可在启动前、退出后进行同步。无需额外部署业务服务端或数据库。

## 主要功能

- **多游戏管理**：每款游戏独立配置、独立保存同步记录。
- **多个存档位置**：一个游戏可同时配置多个文件夹或单个文件。
- **自动同步**：启动游戏前同步，退出后等待存档写入稳定再同步。
- **按修改时间同步**：自动选择最后修改时间较新的一份存档。
- **备份与恢复**：云端保留历史版本，本地覆盖前自动备份，也可离线恢复本地备份。
- **跨电脑使用**：从 WebDAV 导入已有游戏，分别绑定各电脑的本机路径。
- **WebDAV 兼容**：支持 HTTP、HTTPS 和自签名证书，不要求服务器提供 ETag。

## 同步规则

同步以**一款游戏的一整份存档**为单位，不逐个合并文件。程序取已选择的所有存档文件中最新的最后修改时间，统一按 UTC 比较。

| 本地与云端状态 | 自动处理 |
| --- | --- |
| 内容相同 | 不重复上传 |
| 本地修改时间较新 | 上传本地存档，保留云端旧版本 |
| 云端修改时间较新 | 先备份本地，再下载恢复 |
| 时间相同但内容不同 | 停止自动覆盖，提示手动选择 |
| 本地所有存档位置均不存在 | 下载云端当前存档 |
| 无法联网或传输失败 | 保留本地存档，稍后手动重试 |

恢复下载的存档时会保留文件修改时间。早期版本上传的快照如果没有记录修改时间，使用当时的上传时间作兼容比较。

**请保持各电脑系统时间准确。** 时间较新不等于剧情进度更多；所选目录中的设置文件也参与时间比较。发生误选时，可从历史版本或本地备份恢复。

## 下载与编译

当前发布提供源码，需要在 Windows 上编译后运行。

### 环境要求

- Windows 10 / 11。
- .NET Framework 4.8。
- Windows PowerShell，以及系统中的 .NET Framework C# 编译器。

不需要安装 .NET SDK，也不需要下载 NuGet 依赖。

### 编译步骤

1. 在仓库的 **Releases** 中选择版本，下载 **Source code (zip)** 并解压。
2. 在包含 `build.ps1` 的目录打开 PowerShell，执行：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
   ```

3. 编译成功后，目录中会生成 `GalSaveSync.exe`，双击运行。

运行时请保留同目录的 `GalSaveSync.exe.config`，并将程序放在有写入权限的位置。

## 快速开始

### 1. 配置 WebDAV

点击 **WebDAV 设置**，填写地址、用户名和密码，点击 **测试连接和读写**，通过后保存。

地址应是可直接访问文件的 WebDAV 文件夹地址，而不是网盘的网页管理界面，例如：

```text
http://你的服务器:端口/dav/
https://你的域名/dav/
```

程序会在该地址下创建 `GalgameSaves` 文件夹。服务需支持创建目录、上传、下载及列出普通文件；认证使用用户名和密码或应用专用密码。

### 2. 添加游戏和存档位置

点击 **添加游戏**：

- 填写游戏名称。
- 选择实际运行的游戏 EXE。
- 添加具体存档文件夹或单个存档文件，可以添加多个位置。

请选择真正的存档位置，包含需要同步的存档槽位、已读记录或解锁数据。所选文件夹中的文件都会纳入同步，不提供排除规则。

### 3. 建立第一份云端存档

先在游戏中保存一次并退出，再选择该游戏，点击 **上传本地**。

### 4. 日常使用

点击 **同步并启动**：

```text
检查本地和云端 → 按时间同步 → 启动游戏
                                  ↓
                   游戏退出 → 等待写入稳定 → 再次同步
```

游玩期间保持客户端打开。也可在游戏退出后使用 **同步所选**、**上传本地** 和 **历史 / 下载** 手动操作。

## 在第二台电脑上使用

1. 使用一份干净的程序目录，配置同一个 WebDAV 地址和账号。
2. 点击 **导入云端游戏**，选择已有游戏。
3. 设置这台电脑上的游戏 EXE 和对应存档路径。两台电脑的路径可以不同；尚不存在的路径可直接输入。
4. 点击 **同步所选** 或 **同步并启动**。

**不要复制第一台电脑的 `Data` 文件夹作为第二台电脑的配置。** 其中包含设备身份、同步记录及当前 Windows 用户加密的密码。

连接同一款云端游戏时使用“导入云端游戏”；重新添加同名游戏会生成独立条目。建议各电脑使用相同版本的客户端和游戏。

## 备份与恢复

| 操作 | 用途 |
| --- | --- |
| **历史 / 下载 → 下载恢复到本机** | 手动恢复指定云端快照，覆盖前自动备份 |
| **历史 / 下载 → 设为云端当前版本** | 指定其他设备同步时参考的云端版本，其他历史仍保留 |
| **本地备份** | 不联网，备份当前配置的存档 |
| **恢复本地备份** | 不联网，恢复本程序生成且游戏及存档位置定义匹配的 ZIP |

恢复按快照替换整个配置位置，快照中没有的原文件也会被移出当前存档位置，原内容保留在恢复前备份中。下载历史版本只恢复本机，不会自动回退云端；如需其他设备使用该版本，还需设置云端当前版本。

默认本地数据位于 EXE 同级的 `Data` 文件夹：

```text
Data/
├─ settings.json        游戏配置、设备身份和同步记录
├─ settings.json.bak    上一次配置副本
├─ application.log      操作与错误日志
├─ backups/             手动备份和恢复前备份
└─ staging/             恢复暂存目录
```

密码通过 Windows DPAPI 加密，仅同一 Windows 用户可解密。升级程序时关闭旧客户端，替换 EXE 和 `.exe.config`，保留原 `Data` 文件夹即可。

云端历史和本地备份不会自动清理。移除本地游戏条目不会删除真实存档、云端文件或备份。不要随意删除云端 `journal` 中的修订记录，以免破坏同步历史。

## 使用限制与注意事项

- **存档支持范围**：仅普通本地文件和文件夹，需手动配置；不支持注册表存档、网络共享路径、符号链接或目录联接。
- **路径配置**：存档位置不能重叠，不能选择整个磁盘、Windows 目录或程序的 `Data` 目录。上传后可修改本机路径，但增删存档位置需要新建游戏条目。
- **自动运行范围**：一次监控一款游戏，只跟踪从客户端启动的实际 EXE；启动器转交子进程、额外启动参数等情况请手动同步。从外部直接启动游戏不会触发自动同步。
- **传输与容量**：单份快照最多 512 MiB、50000 个文件，每款游戏最多 32 个存档位置。相对文件路径超过 220 字符的快照不能恢复。网络操作没有取消按钮，不支持断点续传或后台定时重试。
- **历史规模**：每游戏最多读取 5000 次修订，单条修订清单最多 16 MiB、清单合计最多 128 MiB。历史增加后检查可能变慢，目录列表延迟或缺失时可能需要稍后重试。
- **恢复中断**：普通恢复失败会尝试回滚；断电、强制结束或文件占用可能需要手动从备份恢复。
- **游戏兼容性**：不能判断剧情进度，也不能保证不同游戏版本、汉化补丁或模拟器的存档兼容。
- **HTTPS 行为**：默认忽略服务器证书验证，包括自签名、过期和名称不匹配。连接仍使用 TLS 加密，但不会验证服务器身份；此行为仅作用于本程序，不修改 Windows 证书设置。
- **认证与地址**：不支持 OAuth、验证码或网页登录，不跟随重定向；地址不能包含查询参数、片段或内嵌账号密码。

首次接入一款游戏时，建议先做一份本地备份。请勿将 `Data`、个人存档或含账号信息的配置提交到公开仓库。

## 问题反馈

通过本仓库的 **Issues** 提交问题，尽量提供：

- 客户端版本、Windows 版本。
- 触发问题的操作步骤。
- 完整错误提示或已遮盖隐私的日志片段。
- 如果与连接有关，注明 WebDAV 服务类型及 HTTP / HTTPS。

请不要公开密码、令牌或真实存档。日志可能含游戏名称、本机路径或服务器地址，提交前请检查。
